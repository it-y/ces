# Infinite Canvas 全量整改设计

日期：2026-07-13

## 1. 目标

在不改变前端 API 路径、请求/响应核心格式、WebSocket 消息类型、本地 JSON 存储和文件可迁移特性的前提下，修复代码审查中确认的全部 P0、P1、P2 问题，使项目达到可稳定长期使用的单机本地应用标准。

## 2. 不变约束

- 保持 localhost 单机部署，不引入数据库、Redis、消息队列或前端框架。
- 保持功能域目录组织，不增加通用 Service/Repository/ABC 层。
- 保持画布 `base_updated_at + 409` 乐观锁语义。
- 保持 WebSocket `stats`、`new_image`、`canvas_updated`、`asset_library_updated` 消息格式。
- 保持 AI 分发顺序：ModelScope → Jimeng → RunningHub → Gemini → Volcengine → OpenAI。
- 不从旧 `main.py` 复制函数体，只参考行为和协议。
- 所有新增文件索引均为可重建缓存，完整 JSON 和资源目录仍是真实数据源。

## 3. 方案选择

### 方案 A：局部打补丁

只补导入、加路径判断、修个别接口。优点是快；缺点是路径、安全、文件事务仍分散，后续会再次出现同类问题。

### 方案 B：按功能域收口并全量修复（采用）

在现有架构上增加少量域内模块，统一路径、文件事务、索引和任务状态；分批保持 API 兼容。改动可控，同时能消除根因。

### 方案 C：整体重写

重新设计后端和前端。风险大、周期长，违反前端零改动和简单优先原则，不采用。

## 4. 核心设计

### 4.1 文件与 URL 安全边界

新增或收口 `app/core/paths.py`：

- `safe_path_join(root, relative)`：拒绝绝对路径、驱动器路径、父目录跳转，解析后确认仍位于根目录。
- `resolve_local_media_url(url)`：唯一解析 `/assets/`、`/output/`、`/cfiles/` 的入口。
- ZIP 路径使用 `PurePosixPath` 校验，限制条目数、单文件大小、总解压大小和压缩比。
- ComfyUI 工作流只接受纯文件名和 `.json` 后缀。
- 本地图片导入只允许已注册共享目录。

新增或收口 `app/core/remote_assets.py`：

- 用户 URL 只允许 HTTP/HTTPS。
- 拒绝 loopback、link-local、私网、保留地址和非预期端口。
- 重定向逐跳验证。
- 流式下载并限制响应大小、超时、并发数。
- data URI 在解码前后均限制大小。

### 4.2 浏览器本地安全

- CORS 只允许 `127.0.0.1:3000` 和 `localhost:3000`。
- 敏感文件、配置、更新、工作流和本地进程 API 统一执行同源校验。
- 保留脚本调用能力，但增加应用启动随机 session token；前端启动页注入或通过同源 bootstrap 获取，敏感 API 使用自定义请求头。
- 不改变现有普通读取接口的响应格式。

### 4.3 画布领域

- 新增 `canvas/import_export.py`，承接 JSON/ZIP 导入、资产打包和工作流导出。
- 所有画布锁统一按稳定 `canvas_id` 获取。
- 新增 manager 原子方法：导入、重命名、追加节点、资源迁移。
- 文件重命名使用同盘临时路径与 `os.replace`，失败时回滚 JSON 和资源目录。
- 新增 `.index.json` 轻量索引，保存列表、项目统计和资产摘要所需元数据；索引可从画布 JSON 重建。
- 回收站清理移出列表请求热路径。

### 4.4 资产领域

- 将索引、工作流库和 Prompt 库从超大 `library.py` 中拆到域内模块。
- 单项 CRUD 增量更新索引；批量操作一次加锁、一次写入。
- 资产响应按索引版本缓存，锁内只提交状态。
- Prompt 条目按稳定 ID 保存，并兼容迁移旧的显示名称文件。

### 4.5 上传和媒体

- 上传、Base64、本地导入和远程导入统一使用临时文件 + `os.replace`。
- 上传和下载过程中计数，禁止先完整读入内存再检查。
- PIL 解码设置最大像素和缩略图尺寸上限。
- ZIP/PIL/目录复制等同步 CPU/IO 使用 `asyncio.to_thread`。

### 4.6 生成任务和 AI 网关

- 任务文件改用 `DATA_DIR` 绝对路径，lifespan 加载，原子保存。
- 启动时将遗留 `queued/running` 修复为 `interrupted`，按 TTL/数量清理。
- 画布节点写入统一调用 manager 原子追加；冲突耗尽时任务记录明确警告并通过 WebSocket 通知。
- 修正六种协议分发顺序。
- 任务查询鉴权下沉到对应 gateway。
- OpenAI/Gemini 参考素材统一使用安全素材加载器。
- 即梦子进程超时执行 terminate/kill，并在 shutdown 清理。

### 4.7 ComfyUI

- 命名工作流先安全加载 JSON，再提交字典。
- 多实例队列状态并发探测，锁内只维护本地预留计数。
- 全部实例不可用时返回 503，不回退到不可用默认实例。
- 实例更新通过 `update_instances()` 原子同步实例列表和负载映射，并持久化。
- 删除未使用的伪队列字段，系统队列状态从真实生成任务和 ComfyUI 状态聚合。

### 4.8 WebSocket

- 连接表使用短持有状态锁。
- 广播使用连接快照、并发发送和单连接超时。
- 失败连接批量清理，只广播一次连接统计。
- 重复 client ID 替换并关闭旧连接。

### 4.9 更新和回滚

实现真实状态机，而不是返回 501：

1. 更新锁防止并发更新。
2. 下载完整允许更新文件清单到同盘 staging。
3. 校验每个响应、路径、文件数量和总大小；任一失败整体终止。
4. 明确排除 `data/`、用户工作流、环境文件、虚拟环境、缓存和运行日志。
5. 创建带版本和时间戳的完整备份清单。
6. 静态目录采用目录级替换，根文件和 Python 包采用临时文件 + `os.replace`。
7. 提交失败按操作日志逆序回滚。
8. 写入 update-state.json，成功后按请求调度重启。
9. 回滚只接受服务端生成的备份 ID，校验清单后执行同样的事务替换。

### 4.10 未实现端点

- 能基于现有模块实现真实状态的端点完成实现，如队列和更新连通性。
- 没有业务实现或外部协议依据的 caption/classify/avatar 等端点明确返回 501，禁止返回虚假成功。
- 前端对应按钮显示“未启用”或正确处理 501。

## 5. 测试策略

严格按回归测试先行：

- 路径：`../`、绝对路径、Windows 驱动器、反斜杠、编码路径。
- ZIP：路径穿越、条目上限、总大小、压缩比。
- API 契约：使用前端真实请求体测试导入、资产下载和 ComfyUI。
- 文件事务：JSON 损坏、写失败、重命名失败、回滚。
- 并发：乐观锁、并发保存、批量资产操作、WebSocket 慢连接。
- 网络：SSRF、重定向、响应超限、超时。
- 后台任务：重启恢复、TTL、即梦超时清理。
- 更新器：使用临时项目目录测试下载失败、提交失败和回滚。
- AI 网关：mock HTTP，覆盖分发顺序和鉴权。

测试工程统一为：

- `pytest.ini` 限定 `testpaths = tests`、`pythonpath = .`。
- tools 下脚本不再被 pytest 收集。
- 明确配置 anyio/pytest-asyncio。

## 6. 迁移与兼容

- 首次启动时若索引缺失或损坏，从原始文件重建。
- Prompt 名称文件迁移为 ID 文件前先备份，迁移可重复执行。
- 任务旧文件兼容读取，未知字段保留或忽略，不阻断启动。
- 不批量改写现有画布 JSON，只有用户保存或执行明确迁移时更新。
- 更新器永不覆盖 `data/`，用户文件不参与程序版本替换。

## 7. 实施顺序

1. 测试工程和安全基础设施。
2. P0 路径、ZIP、导入、CORS、工作流和更新器。
3. 画布事务、资产下载、JSON 损坏和 Prompt 迁移。
4. 生成任务、AI 网关、ComfyUI 和 WebSocket。
5. 画布/资产索引及阻塞 IO 优化。
6. 模块拆分、占位端点处理、前端错误展示。
7. 全量编译、测试、关键端点冒烟和整改清单复核。

## 8. 完成标准

- 审查报告中的 P0、P1、P2 均有代码处理或明确的真实 501 行为。
- 现有 API 路径和核心响应字段保持兼容。
- 所有正式测试通过，并新增高风险回归测试。
- `pytest -q` 与 `python -m pytest -q` 结果一致。
- 编译检查通过。
- 不存在已知裸路径拼接的本地文件读取/写入入口。
- 更新和回滚通过临时目录事务测试。
- 无需数据库、前端框架或分布式组件。
